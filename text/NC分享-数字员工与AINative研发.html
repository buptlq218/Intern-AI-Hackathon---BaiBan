04 · 开放 — 两种接入模式

尚无深度 Agent 实践
已有自研 Agent / 工作流
资产接入 (装载到数字人)模式一 · 大多数团队

上层数字人以资产方式扩展业务能力 — 知识与能力装载给恩熙, 直接用 NC 数字员工

  • 知识 / 轻量 Skill 直接上翻: 管理台挂载, 拉群即生效
  • 代码仓库 + 文档一键初始化: bk-scan + 知识编译 → 初始业务资产
  • 已有知识服务 (KBase 等) 直接对接, 统一出口消费

详见下页 · 装载解耦 · 分层开放

子 Agent 接入 (子 Agent 进程承载)模式二 · 已有自研 Agent 的团队

深度垂直场景的能力定制 — 自有工作流原样保留, 注册为恩熙的子 Agent

  • run / resume 协议注册: npm 包 (已支持) · HTTP API (规划)
  • 默认需求分析 / 交付 Agent (含 CI/CD) 不可删除, 以自有 Skill 定制
  • 载体任选: Claude Code / Qoder CLI — Prompt · Skills · MCP · Hooks 均可扩展

详见后页 · 子 Agent 开放注册

殊途同归 — 同一个数字员工 · 同一个资产底座对业务方是同一个恩熙

上层拉平协作, 下层保留控制 — 管理归平台 · 专业归团队; 开放是手段, 沉淀天猫全域业务资产是目的
