# Loop 实验记录

> 第一军规：**先写怎么停，再写怎么跑。写不出完成标准，就不要让循环开始。**

规则：
- 每轮**只改一个**主变量。同时改两个，结果就无法归因。
- 先写「成功标准」和「回退条件」，再动代码。
- 连续 2–3 轮无改善 → 换方向，不要在同一个假设上继续磨。
- 判断依据是**趋势、方差和最差情况**，不是最好的那一局。

## R0 —— 赛前基线（离线沙盒建立）

时间：赛前  |  版本：firefly-v1  |  基线：无

### 做了什么
搭出完整策略引擎 + 71 个单测 + 离线沙盒。沙盒发现并修掉三个真 bug：

1. **单位错误**：`velocity` / `speed` 是 **px/frame** 不是 px/s，导致「前瞻 1.2 秒」
   实际只看了约 6px。这是避障失效的根因。
   → `geometry.extrapolate` 参数改为帧数，新增 `seconds_to_frames`。
2. **梭哈过早**：窗口末尾 5s 内梭哈全部能量，赢 1 次后能量归零，
   随后 1.5s 一次连输三次，净 -2。
   → `attack.py` 增加按碰撞冷却计算的保留额。
3. **避障被优先级阶梯绕过**（影响最大）：`seek_heart` 排在避障之前，
   追道具时完全不避障，clearance 从 128 一路磨到 0，最后撞墙淘汰。
   → 避障从「阶梯里的一根横杆」改成 `plan_motion` 里的**运动层滤波**，
   对所有未显式 opt-out 的意图统一施加。

### 沙盒结果（20 局，对手 default/steady/aggressive）

| 阶段 | 平均果实 | 平均名次 | 晋级率 |
|---|---|---|---|
| 初版 | 1.20 | 2.80 | 60% |
| 修单位 + 梭哈保留额 | 5.85 | 2.20 | 60% |
| 修避障架构 | 5.90 | **1.60** | **80%** |

### 结论
保留。作为赛前锁定的可回退基线。

⚠️ **沙盒是近似模型，不是引擎复刻**（物理步进、碰撞判定、对手行为都是代理）。
所以以上数字只用于「排除坏参数 / 防回归崩溃」，**不能当作策略更强的证据**。
真实结论必须来自联调平台 replay。

### 下一轮唯一优先项
到现场先跑通链路，然后按 `docs/EXPERIMENTS.md` 的 P0（E1–E4）验证规则，
**不要先调参**。E1（边缘是否算障碍碰撞）可能直接白送 2 分/30s。

## R1 —— 接入官方 SDK，并据真实契约与新规则修正策略

时间：赛前（拿到 `participant-bot-starter-python` 后）  |  版本：firefly-v1  |  基线：R0

### 从真实 SDK 读到的、和文档不一样的事实

1. **`refreshData.data` 里没有 `elapsedSeconds` / `remainingTime`**，只有 `rabbits`
   和 `goldCarrot`（技术细则的字段表里有，实际 SDK 没有）。但两个 30s 周期都依赖时间
   → 改成本地单调时钟，在 `on_start_game` 对零；能量重置相位仍由观测二次校正。
2. **官方 `choose_command` 拿不到 `map`** → 避障本来做不了。在 `bot.py` 的
   `startGame` 分支加了一个可选 hook 透传 data。这是对 `bot.py` 的唯一改动。
3. **`choose_command` 必须返回合法 dict，不能返回 None**（`normalize_command` 会抛，
   降级成 `stop`）。而引擎在「状态无变化」时本应什么都不发 → 这种帧重发上一条
   **移动**指令（幂等，不打断持续转向）。
4. **转向符号确定了**：官方基准用 `turnRight if delta > 0 else turnLeft`，
   即 turnLeft 使 angle 减小。E3 从「待验证」变成「已确认」，标定默认值改为 -1。
   （在线标定保留，以防版本差异。）
5. **`setAttackValue.data` 上限 1000**，转向 data 严格 0.01~0.1，越界直接抛。
6. 新增消息 `seriesGameStarted`：同桌下一局会换房间号，`bot.py` 已处理；
   我们的 hook 每局都会重新触发，状态自然清干净。

### 从《规则宣讲&QA》读到的新规则

**积分规则（此前三份文档都没有）**：每组 3 轮，每轮按名次积 3/2/1/0 分；
总积分相同取发光果实多者。收益因此是**不对称**的 —— 掉到第 4 名直接 0 分，
而果实还是总榜第一顺位 tiebreak。

→ 新增终局姿态 `protect` / `normal` / `desperate`（`Tune.endgame_seconds` 等三个参数）。

### 沙盒发现并修掉的两个策略缺陷

**缺陷 A：把「打不赢」等同于「该躲」。** 平局不丢果实，且免费重置无碰撞计时，
所以能打平就该打。旧逻辑在「三个对手全部梭哈 1000」时判定全场避战，
整局靠撞障碍保活 → 平均果实 -0.70、晋级率 27%。

**缺陷 B（更重要）：算威胁时忽略了对手的当前能量。**
`actualAttack = min(设定, 能量)`，所以对手当前能量是他攻击强度的**硬上限**。
梭哈型对手花完 1000 之后，整个窗口剩余时间能量都是 0 —— 完全无害，
最小出价就能白拿 +1。旧逻辑只看历史出价，把空壳一直当 1000 的威胁躲着走。

修法：`threat_of()` 按对手当前能量截断；目标打分新增 `w_target_drained` 项，
优先打能量见底的对手。

### 结果（沙盒各 40 局）

| 对手组合 | 平均果实 | 平均名次 | 晋级率 |
|---|---|---|---|
| 全默认 | 11.35 | 1.18 | 92% |
| default/steady/aggressive | 6.90 | 1.68 | 75% |
| steady/aggressive/allin | 3.58 | 2.38 | 52% |
| 全梭哈 | 1.27 | 2.35 | 55% |

「全梭哈」场景：晋级率 27% → 55%，平均果实 -0.70 → 1.27。

回归：`mytests/run_all.py` 106 passed；官方 `check.py` all checks passed。

### 结论
保留。作为正式赛的可回退基线。

### 下一轮唯一优先项
到现场先跑通链路 + 看一局真实 replay，然后验 `docs/EXPERIMENTS.md` 的 **E1**
（边缘接触是否算障碍碰撞、是否重置无碰撞计时）。若是「不扣分 + 重置计时」，
保活就完全免费，直接白赚 2 分/30 秒 —— 这是目前已知收益最高的单点改动。
**不要先调参。**
