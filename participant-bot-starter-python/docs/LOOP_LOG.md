# Loop 实验记录

> 第一军规：**先写怎么停，再写怎么跑。写不出完成标准，就不要让循环开始。**

规则：
- 每轮**只改一个**主变量。同时改两个，结果就无法归因。
- 先写「成功标准」和「回退条件」，再动代码。
- 连续 2–3 轮无改善 → 换方向，不要在同一个假设上继续磨。
- 判断依据是**趋势、方差和最差情况**，不是最好的那一局。

## R0 —— 赛前基线（离线沙盒建立）

时间：赛前  |  版本：firefly-v1  |  基线：无

### 做了什么
搭出完整策略引擎 + 71 个单测 + 离线沙盒。沙盒发现并修掉三个真 bug：

1. **单位错误**：`velocity` / `speed` 是 **px/frame** 不是 px/s，导致「前瞻 1.2 秒」
   实际只看了约 6px。这是避障失效的根因。
   → `geometry.extrapolate` 参数改为帧数，新增 `seconds_to_frames`。
2. **梭哈过早**：窗口末尾 5s 内梭哈全部能量，赢 1 次后能量归零，
   随后 1.5s 一次连输三次，净 -2。
   → `attack.py` 增加按碰撞冷却计算的保留额。
3. **避障被优先级阶梯绕过**（影响最大）：`seek_heart` 排在避障之前，
   追道具时完全不避障，clearance 从 128 一路磨到 0，最后撞墙淘汰。
   → 避障从「阶梯里的一根横杆」改成 `plan_motion` 里的**运动层滤波**，
   对所有未显式 opt-out 的意图统一施加。

### 沙盒结果（20 局，对手 default/steady/aggressive）

| 阶段 | 平均果实 | 平均名次 | 晋级率 |
|---|---|---|---|
| 初版 | 1.20 | 2.80 | 60% |
| 修单位 + 梭哈保留额 | 5.85 | 2.20 | 60% |
| 修避障架构 | 5.90 | **1.60** | **80%** |

### 结论
保留。作为赛前锁定的可回退基线。

⚠️ **沙盒是近似模型，不是引擎复刻**（物理步进、碰撞判定、对手行为都是代理）。
所以以上数字只用于「排除坏参数 / 防回归崩溃」，**不能当作策略更强的证据**。
真实结论必须来自联调平台 replay。

### 下一轮唯一优先项
到现场先跑通链路，然后按 `docs/EXPERIMENTS.md` 的 P0（E1–E4）验证规则，
**不要先调参**。E1（边缘是否算障碍碰撞）可能直接白送 2 分/30s。

## R1 —— 接入官方 SDK，并据真实契约与新规则修正策略

时间：赛前（拿到 `participant-bot-starter-python` 后）  |  版本：firefly-v1  |  基线：R0

### 从真实 SDK 读到的、和文档不一样的事实

1. **`refreshData.data` 里没有 `elapsedSeconds` / `remainingTime`**，只有 `rabbits`
   和 `goldCarrot`（技术细则的字段表里有，实际 SDK 没有）。但两个 30s 周期都依赖时间
   → 改成本地单调时钟，在 `on_start_game` 对零；能量重置相位仍由观测二次校正。
2. **官方 `choose_command` 拿不到 `map`** → 避障本来做不了。在 `bot.py` 的
   `startGame` 分支加了一个可选 hook 透传 data。这是对 `bot.py` 的唯一改动。
3. **`choose_command` 必须返回合法 dict，不能返回 None**（`normalize_command` 会抛，
   降级成 `stop`）。而引擎在「状态无变化」时本应什么都不发 → 这种帧重发上一条
   **移动**指令（幂等，不打断持续转向）。
4. **转向符号确定了**：官方基准用 `turnRight if delta > 0 else turnLeft`，
   即 turnLeft 使 angle 减小。E3 从「待验证」变成「已确认」，标定默认值改为 -1。
   （在线标定保留，以防版本差异。）
5. **`setAttackValue.data` 上限 1000**，转向 data 严格 0.01~0.1，越界直接抛。
6. 新增消息 `seriesGameStarted`：同桌下一局会换房间号，`bot.py` 已处理；
   我们的 hook 每局都会重新触发，状态自然清干净。

### 从《规则宣讲&QA》读到的新规则

**积分规则（此前三份文档都没有）**：每组 3 轮，每轮按名次积 3/2/1/0 分；
总积分相同取发光果实多者。收益因此是**不对称**的 —— 掉到第 4 名直接 0 分，
而果实还是总榜第一顺位 tiebreak。

→ 新增终局姿态 `protect` / `normal` / `desperate`（`Tune.endgame_seconds` 等三个参数）。

### 沙盒发现并修掉的两个策略缺陷

**缺陷 A：把「打不赢」等同于「该躲」。** 平局不丢果实，且免费重置无碰撞计时，
所以能打平就该打。旧逻辑在「三个对手全部梭哈 1000」时判定全场避战，
整局靠撞障碍保活 → 平均果实 -0.70、晋级率 27%。

**缺陷 B（更重要）：算威胁时忽略了对手的当前能量。**
`actualAttack = min(设定, 能量)`，所以对手当前能量是他攻击强度的**硬上限**。
梭哈型对手花完 1000 之后，整个窗口剩余时间能量都是 0 —— 完全无害，
最小出价就能白拿 +1。旧逻辑只看历史出价，把空壳一直当 1000 的威胁躲着走。

修法：`threat_of()` 按对手当前能量截断；目标打分新增 `w_target_drained` 项，
优先打能量见底的对手。

### 结果（沙盒各 40 局）

| 对手组合 | 平均果实 | 平均名次 | 晋级率 |
|---|---|---|---|
| 全默认 | 11.35 | 1.18 | 92% |
| default/steady/aggressive | 6.90 | 1.68 | 75% |
| steady/aggressive/allin | 3.58 | 2.38 | 52% |
| 全梭哈 | 1.27 | 2.35 | 55% |

「全梭哈」场景：晋级率 27% → 55%，平均果实 -0.70 → 1.27。

回归：`mytests/run_all.py` 106 passed；官方 `check.py` all checks passed。

### 结论
保留。作为正式赛的可回退基线。

### 下一轮唯一优先项（已由 R2 接手）
到现场先跑通链路 + 看一局真实 replay，然后验 `docs/EXPERIMENTS.md` 的 **E1**
（边缘接触是否算障碍碰撞、是否重置无碰撞计时）。若是「不扣分 + 重置计时」，
保活就完全免费，直接白赚 2 分/30 秒 —— 这是目前已知收益最高的单点改动。
**不要先调参。**

## R2 —— 转向角速度档位：(0.02, 0.05, 0.1) → (0.1,)

时间：现场练习赛后  |  版本：firefly-v2  |  基线：R1（strategyHash 9f9cfc0d 的 4 局练习赛）

### 假设

**replay 证据**（`python3 tools/analyze.py runtime/`，4 局练习赛）：

| 局 | 果实 | 名次 | 赢 | 输 | 撞障碍 |
|---|---|---|---|---|---|
| b001 | 0（淘汰） | 4 | 0 | 1 | 6 |
| b008 | 4 | 1 | 9 | 2 | 13 |
| b020 | 8 | 1 | 6 | 0 | 6 |
| b033 | 14（未完） | 1 | 6 | 0 | 11 |
| 合计 | | | **21** | **3** | **36** |

**撞障碍(36) > 赢(21)。** 对局本身是赢的（21:3，87.5%），全部损失来自撞墙。

排除了三种其它解释，每一条都有证据：

1. **不是「地图没缓存」** —— 把真实 `startGame.data` 喂给 `protocol.Frame.parse`，
   得到 4 个障碍凸块 + 27 个边界凸块，解析正常。
2. **不是「零能量输局被误分类」** —— 逐个事件回查当时我方能量与最近对手距离：
   36 次里 33 次能量充足（1000/846/924…）且 120px 内无对手，是真撞障碍。
3. **不是撞边缘** —— 30 次里 29 次距石头 37~86px 而距边缘 100~400px。
   （顺带回答 E1：边缘不是损失源，`border_keepout=70` 不用动。）

**真正的根因是转向增益**。`control.py:133`：

```python
desired_rate = min(RULE_TURN_RATE_MAX, abs_err / math.pi * RULE_TURN_RATE_MAX)
```

角速度按「误差 ÷ π」线性缩放，于是：

| 航向误差 | 实际档位 | 纠正耗时 |
|---|---|---|
| 45° | 0.02 | **3.9s** |
| 57° | 0.02 | **5.0s** |
| 90° | 0.05 | 3.1s |

而巡航 40~50 px/s、离石头 37~86px → **只有约 1 秒反应时间**。避障算得再准也来不及。
还有个反常处：45° 要 3.9s 而 90° 只要 3.1s，误差越大反而转得越快 —— 增益标定错了。

这也说明 `analyze.py` 印出的诊断「调大 obstacle_safety_margin」**是错的**：
余量再大，以 11°/秒 照样撞进去。

- **本轮只改**：`Tune.turn_rate_buckets` `(0.02, 0.05, 0.1)` → `(0.1,)`
  单一档位使 `bucket_turn_rate` 恒返回 0.1，**绕过**那条坏增益公式（只动 TUNE，
  不动引擎代码）。附带好处：档位不再抖动，`emit` 不会再为「速率变了」浪费动作位。
- **预期行为**：避障能在 1 秒内完成大角度纠正，不再出现「每 2 秒撞一次」的磨墙序列。
- **成功标准**：撞障碍次数从 ~9 次/局 降到 ≤3；果实均值不降；最差情况不变差。
- **回退条件**：出现追击时绕着目标画圈/反复过冲（表现为赢的次数下降），
  或果实均值下降 >1，或出现新的淘汰。

### 结果（沙盒各 60 局，四种对手组合）

| 对手 | 基线 均值/最差/名次/晋级 | (0.1,) 均值/最差/名次/晋级 |
|---|---|---|
| 全默认 | 11.40 / 0 / 1.17 / 93% | **16.43** / 0 / 1.22 / 90% |
| default/steady/aggressive | 6.65 / **-2** / 1.72 / 75% | **11.77** / **0** / 1.08 / 98% |
| steady/aggressive/allin | 3.62 / **-2** / 2.30 / 55% | **8.82** / **0** / 1.08 / 100% |
| 全梭哈 | 1.30 / **-2** / 2.35 / 57% | **6.60** / **0** / 1.17 / 97% |

四种组合全部同向改善，**最差情况一律从 -2 变成 0** —— 这正是锁版要看的数字。
唯一的小退让是「全默认」的名次 1.17→1.22、晋级 93%→90%（n=60，在噪声范围内），
而同场景果实从 11.40 涨到 16.43。

回归：`python3 mytests/run_all.py` 131 passed；官方 `check.py` all checks passed。

### 结论

保留。证据强度高于普通调参：**算术推导与沙盒是两条独立证据且同向**
（前者完全不依赖沙盒模型）。

⚠️ 仍需现场 replay 确认：沙盒的转向物理是代理模型。下一局跑完必须回看
`analyze.py` 的「撞障碍」次数，若没有明显下降就回退。

### 下一轮唯一优先项

用真实 replay 验证本轮（撞障碍是否 ≤3 次/局）。若成立，下一个目标是
**森林之心**：4 局只拿到 1 次心，而 `RULE_HEART_SPAWN_HINTS` 至今只有沙盒在读，
策略从未预定位（`grep` 已确认）。一次心值 +3~+6 果实，是剩下最大的一笔钱。

## R3 —— 能量纪律：不再全押 + 按目标出价 + 底线保命

时间：现场（8 局练习赛后）  |  版本：firefly-v3  |  基线：R2（**注意：R2 尚未被真机验证**）

### 假设

来源：队友的实战观察「经常双方能量都归零，一直无效碰撞」。**验证后一半成立、一半需修正。**

**replay 实测（8 局，全部 strategyHash 9f9cfc0d）**：

| 指标 | 数值 |
|---|---|
| 我方能量=0 的帧占比 | **22%**（b001 达 65%） |
| 能量=0 时挨的 -1 | **20 次** |
| 「所有对手同时归零」的可利用窗口 | **0 次** |

→ 所以**不是双方归零，是我们单方面被打空**。对手基本恒定出价 50（官方默认），
不会耗尽。「最后阶段设 1 一直赢」在当前对手池不会触发；但「留一手」是对的。

**为什么会被打空**，b077 的出价序列给了答案：

```
154 → 212 → 285 → 218 → 0(7.3s)  ...重置...  257 → 76 → 257 → 1 → 201 → 322 → 155 → 0
```

反解 `bid = threat×1.12+20` → 威胁估计 120 → 171 → 219 → 273 一路爬。
**一个升级型对手把我们的出价抬着走**，而我们比他多花 12%，所以先归零。

**找到一个真 bug**：`strategy.decide()` 出价用 `world.threat_level()`（**全场最大值**），
但一次碰撞只和**一个**对手结算。A 有 800 能量、B 只剩 0 时，冲着 B 去却按 A 出价。
`_best_target` 打分用的是 per-rival 的 `threat_of`，两处不一致。

**本轮改动**（三处，同一机制的三个面，单独任一处都不足）：

1. `strategy.decide()` 改用新的 `worldmodel.threat_for_contact(target_id, me)` ——
   按将要撞的那个对手出价；但把「比目标更近的对手」也算进去，防止瞄弱敌被强敌偷袭。
   `Intent` 新增 `target_id` 字段贯穿 ram / idle_ram / heart_rampage。
2. `attack.py` 取消两条全押路径：
   - 新增 `lean` 模式：能压过但凑不满余量 → 出 `threat + min_attack`，剩下留着。
   - `starved`（连平都做不到）→ 押 `energy - floor` 而不是全部。
     *保留押注*是因为 `threat` 刻意偏高（0.9 分位数并与最近一次取 max），高估很常见，
     押上去是唯一翻盘机会；*保留底线*是因为归零后每次碰撞都是确定的 -1。
   - `spenddown` 也扣掉底线。
3. `min_attack` 60→**2**，`bid_margin_abs` 20→**3**，新增 `energy_floor`=**20**。
   旧的 60/20 正好挡死「对手见底 → 出个位数白拿 +1」这条最便宜的路径。

**底线取 20 是从 replay 反推的**（队友原提的 10 偏小一半）：把每次归零挨的 -1
拿出来算「要赢它需要出多少」（= 对手当次实际出价 +1）：

```
底线  5 → 救回  5/20      底线 20 → 救回 15/20   ← 拐点
底线 50 → 救回 15/20      底线100 → 救回 18/20（占 10% 窗口预算）
```

对手多数只出 10~50（**能量高但出价低**），20 就能压过绝大多数；再往上边际收益为零。
沙盒独立扫描一致：floor 0/10/20 持平，50/100 开始掉均值。

- **成功标准**：`analyze.py` 的「我方能量=0 的帧占比」从 22% 降到 <5%；
  输的次数下降；果实均值不降。
- **回退条件**：果实均值下降 >1，或输的次数上升（说明出价压过头变成压不过了）。

### 结果（沙盒）

| 对手 | R2 参数 | R3 参数 |
|---|---|---|
| 全默认 n=150 | 15.32 ± 0.63 | 15.40 ± 0.62 |
| default/default/aggressive n=150（异质，R3 的目标场景） | 13.65 ± 0.58 | **14.29** ± 0.56 |
| s/a/allin n=60 | 10.22 | 10.40 |
| 全梭哈 n=60 | 5.82 | 5.92 |

⚠️ **沙盒无法验证 R3 的主要收益**，这是结构性的：每个组合内的对手是同质的，
所以「按目标出价」没有可利用的能量差异（全默认时 per-target ≡ 全局最大）。
现场恰恰是异质的 —— 一个升级型对手混在一群出 50 的里面。

所以沙盒在这里只承担它该承担的职责：**证明没有回归**。R3 的真正依据是
真机 replay 的实测数字（22% 归零、20 次白送、对手只出 10~50 而我们出 154~326）。

回归：`mytests/run_all.py` **141 passed**（新增 10 条 R3 用例）；`check.py` all passed。

### 一个被测试逼出来的语义修正

初版把底线写成「任何模式都不得跌破」，被自己的用例抓出反例：
能量 25 / 威胁 10 时出 14 能拿 +1 并剩 11，比守着 20 输掉 -1 好两个果实。
→ **底线只约束两条浪费路径**（`spenddown` 倾倒盈余、`starved` 注定输的赌注），
**不挡能赢的出价**。底线的目的是保住「赢的能力」，不是囤能量。

### ⚠️ 归因风险与对策

R2（转向）**从未被真机跑过**（8 局全是旧 hash），现在 R3 叠在上面。
但两者的验证指标是**正交**的，所以即使捆绑也能分别归因：

- R2 → 「撞障碍」次数（当前 93 次 / 8 局 ≈ 11.6 次每局）
- R3 → 「我方能量=0 的帧占比」（当前 22%）+ 输的次数

任一指标没改善就单独回退对应的那一项。

### 下一轮唯一优先项

**重启 BOT 后跑几局，看这两个指标。** 若都改善，下一个目标是森林之心
（8 局只拿到 1 次，`RULE_HEART_SPAWN_HINTS` 至今只有沙盒在读，策略从未预定位）。

## R2/R3 的真机验证结果 —— 以及一条**必须先纠正的错误结论**

### ❌ 我上一轮说「R2 从未被真机跑过」，这个判断是错的

依据是「8 局的 `strategyHash` 全是 `9f9cfc0d`」。但 `bot.py:64` 写的是：

```python
STRATEGY_HASH = hashlib.sha256((BASE_DIR / "strategy.py").read_bytes()).hexdigest()
```

它**只对顶层 `strategy.py` 做哈希**。R2/R3 改的全是 `firefly/` 里的文件，
所以 hash 一个字节都不会变。23 局全是同一个 hash 是**必然**，与是否重启无关。
**会说谎的版本号比没有版本号更危险** —— 我拿它当证据，反而把真实结论说反了。

真正能认出版本的是 `commands.jsonl` 里的**指令指纹**：

| 组 | 局数 | 转向档位取值 | 出价特征 | 判定 |
|---|---|---|---|---|

## R4：撞障碍的真正机制（10.4 次/局 = 当前最大单项损失）

### 排查过程（每一步都排除一个假设）

| 假设 | 检验 | 结果 |
|---|---|---|
| 那些 -1 其实是零能量输掉的对局，误判成障碍 | 逐事件比对最近石头/最近对手距离 | ❌ 83 次里 58 次贴着石头（最近对手 300~460px），只有 3 次是误判 |
| 是故意撞的（`idle_hit_obstacle` 用 -1 买 -3） | 统计撞击瞬间的上层意图 | ❌ **0 次**故意；71% 发生在 `patrol` |
| 地图没解析进来，避障根本没数据 | 回放喂进策略看 `block_hulls` | ❌ 4 块，正常 |
| 危险检测失灵 | 回放逐帧调 `_imminent_obstacle` | ❌ **83/83 撞击前都报警了（100%）** |
| 检测太晚，物理上来不及 | 量连续预警时长 | ✅ **中位 0.30s，87% 不足 0.5s** |

### 根因（两条，互相加强）

1. **预警只有 0.30s，而脱离需要 1.6s。** 最后一个报警帧：石头在正前方 31°、
   距离 53px、速度 5px/帧 ≈ 1.0s 到达；切向脱离要转约 90°，按 0.1rad/帧要 1.6s。
   而 94% 的情况我们仍在前进（70/83 帧发的是 `goForward`）—— 一边全速朝石头开
   一边慢慢打方向。
2. **巡航目标点本身就在危险区里。** `map_center()` = (720, 410) 到最近石头只有
   **51.8px**，而触发半径是 49.5(精灵) + 26(余量) = **75.5px**。于是
   「开过去 → 报警 → 绕开 → 又被目标点拉回」无限循环。这解释了那 71%。

### 改动

- `control.avoid_obstacle`：石头在**正前方**（closing > 0.7）**且已在转弯半径内**
  （gap < 速度/角速度 = 50px）时 → **倒车**降低闭合速度，转向照常继续。
- 新增 `worldmodel.safe_point_near()` / `rally_point()`，把中场点推出警戒圈；
  `patrol` / `conserve` / 避障的 `goal` 全部改用它。

### 一个被数据抓住的过度修正

第一版判据是「转到脱离航向的时间 > 撞上的时间就刹车」。回放显示：追击中的 305 个
报警帧里有 **149 帧（49%）** 本来正朝着目标前进，被改成了倒车，累计白丢约 15s
接近时间。原因是它要求转完整个 90°，而实际上侧向挪开一点就能擦过去。
换成上面的几何判据后误伤降到 **30%**，同时仍覆盖 **87%** 的历史撞击。

- **成功标准**：撞障碍从 10.4 次/局 降到 ≤4；果实均值不降。
- **回退条件**：撞障碍没降，或追击明显变迟钝（赢的次数下降 >1.5/局）。

## R5：森林之心卡位（队友提的思路，改成自适应版本）

### 两条前置事实，都是实测的

- **E6 ✅ 时刻确认**：`goldCarrot` 首次出现 **15/15 局都在 30.0s**（误差 ≤0.1s），
  第二次在 90.0s。与 `RULE_HEART_SPAWN_HINTS` 一致。
- **生成范围不是全图随机**：x ∈ [423, 1079]、y ∈ [255, 629]，质心 (779, 420)。
  地图是 1440×820，也就是只落在**中央约 46%×46%** 的区域。这一条让卡位的收益
  比「全图随机」假设下大得多。

### 现状有多差

生成瞬间我方到心的距离排名 **平均 2.57**，抢到第一 **14%**。
四人局纯随机就是 2.50 —— **我们的站位毫无优势**。平均距离 524px，对手 213px。

### 做法：最大覆盖，而不是站死一个点

`worldmodel.heart_preposition_point()`：在生成区撒候选点，对每个候选点数一数
生成区采样里「我方 ETA < 所有对手 ETA」的比例，取最高。这会**自动**产生队友描述的
那个行为（三个对手挤在左上角 → 我站到外侧覆盖其余大半张图），而不用把特例写死。

为什么不直接站质心：质心在实测样本上评分更低（47% vs 自适应 67%），且无法利用
对手扎堆。为什么不把网格最优的 (880,540) 写死：那是对 n=15 的**过拟合**。

### 结果（用 t≈24s 的真实对手站位反算 t=30s 的真实生成点，n=14）

| | 实际 | 卡位后 |
|---|---|---|
| 平均排名 | 2.57 | **1.71** |
| 抢到第一 | 14% | **43%** |
| 到心距离 | 524px | 239px |

`heart_preposition_lead` 也是扫出来的，不是拍的（第一版拍 6s，反算发现要走
334px 而 6s 只够 300px，只有 29% 真能站到位）：

```
lead    平均排名  抢到第一  真能走到
 4s      1.86      36%       7%
 6s      1.79      36%      29%
 8s      1.46      62%      77%   ← 选它
10s      1.77      38%      69%
12s      1.92      31%      92%
15s      1.46      69%     100%
```

排名列在 8/10/12/15s 之间**非单调**，n=14 撑不起这种差异，所以不拿它选参数；
能信的是「真能走到」那一列（单调）。8s 吃下 29%→77% 那一跳，且放弃的进攻时间最少。

**安全性**：卡位排在阶梯第 7.5 位，在「无碰撞保活」（第 5 位，20s 触发）之后，
所以卡位期间即使一直没碰撞，保活也会抢先接管，不会因为卡位吃 -3。

- **成功标准**：森林之心获得次数上升（当前 15 局 5 次）；生成瞬间排名 <1.9。
- **回退条件**：果实均值下降 >1，或吃到空转 -3。

## R6：「思想与行为不一致」—— 督战时观察到的执行层缺陷

队友现场反馈：*对方能量很低时没果断追击；对方拿心时没果断朝合理方向逃*。
这不是策略问题，是**操作能力**问题。量化后确认了，而且根因是一行判据：

```python
if allow_reverse and abs_err > self.tune.reverse_threshold and me.speed < 1.0:
```

两个条件都难满足（143° **且** 几乎停住），结果 **4817 条移动指令里只有 25 条
（0.5%）是倒车**，倒车等于死代码。于是航向误差在 90°~180° 之间时我们一直
「朝前开 + 慢慢打方向」，而朝前开正在**远离**目标：

- 追击帧里 **17%** 车头与目标夹角 >90°（在往反方向开）
- 逃跑帧里 **39%** 车头还朝着追我的人 ← 正是「不果断」

### 为什么可以放心倒车

实测 `goBack` 的速度中位数 **5.00 px/帧**，与 `goForward` **完全相同**。
所以只要目标落在车身后半平面（|err|>90°），倒车就严格优于前进：
前进的靠近分量是 cos(err)<0（在跑远），倒车是 -cos(err)>0（在靠近）。
碰撞只看车身接触、不看朝向，所以倒着撞一样算。

### 改动

1. 倒车判据改成**几何**判据 + 100°/80° 迟滞（避免在 90° 附近每帧翻转指令）。
2. `evade_point` 掺入「往空旷处」的分量。纯反方向会把自己逼进墙角，而持心方是
   零成本必胜，贴墙就是站着挨打。**逃跑的目标不是「离他最远」，而是「能一直
   保持距离」。**

### 结果（同一批真实状态上重算指令方向）

| | 旧（几乎恒前进） | 新 |
|---|---|---|
| 追击时朝正确方向移动 | 89% | **99%** |
| 逃跑时朝正确方向移动 | 61% | **97%** |

（含 R4 刹车后分别是 86% / 72% —— 刹车会主动牺牲一点接近速度去换 -1，
这是有意的权衡：追击每局只损失约 0.2s，而撞障碍每次是确定的 -1 果实。）

- **成功标准**：赢的次数上升；被持心对手撞到的次数下降。
- **回退条件**：赢的次数下降，或出现「倒车倒进石头/边界」的新型损失。

回归：`mytests/run_all.py` **160 passed**（新增 19 条 R4/R5/R6 用例）；
`check.py` all passed。

### ❌ 量具故障：我的回放探针让策略以为时间没走

我用「循环调 `strategy.choose_command`」来观察意图分布，得出「conserve 占 76%、

受影响 / 未受影响的结论，逐条交代：

- ❌ 作废：v4 的意图分布数字（conserve 76% / yield 53%）。

另外它**故意不排除碰撞冷却中的对手** —— 冷却是暂时的，若算进去，所有对手刚好都

保护，**是对的**。我最初的用例把三个对手全摆在 260px 内，是用例错了不是代码错了。

### R8 —— ETA 竞速只在刷新那一瞬间有意义

实测森林之心通常在生成后 **1.3~2.7s** 内被抢走（一场瞬间的抢地皮）。而

已经在原地放了 84 秒**。

## R9：队友提的「狮子与人」—— 哪一半能用，哪一半不能

结论:**核心洞见能用，定理本身不能照搬。**

先说前提是否成立（实测）：

- ✅ **等速成立**：持心方速度中位 **5.00** px/帧，我方正常 4.63、上限同为 **5.00**。
  **持心不加速**。所以「等速追逃」这个前提是真的。
- ❌ **瞬间折向不成立**：Besicovitch 的构造要求每段都垂直于当前连线、瞬间折向。
  这里是车式运动，角速度上限 0.1 rad/帧，转 90° 要约 **1.6s**。
- ❌ **圆盘不成立**：这里是 1440×820 的矩形，还有石头。**角落是陷阱，圆盘没有角落。**

所以「一定能逃掉」不成立，但那条可执行的结论成立并且已采用：
**沿垂直于连线的方向跑，而不是径向后退** —— 径向后退在有界场地里必然把自己推到
边界，而持心方零成本必胜，贴墙就是站着挨打。

实现上踩了一个坑,被自己的用例抓住:切向瞄点的径向分量很小,若把「前进还是后退」
也交给 `steer_towards` 按瞄点误差去判,会得出**朝追兵开**的结论(反例:追兵在车头
右前方 30°、切向瞄点在 -60°,误差 60° 判前进 → 每帧朝追兵靠近 cos30°=0.87 身位)。

→ **位移方向必须单独判，判据只有一条：这一帧的位移在「远离追兵」方向上的投影必须
为正。** 位移只有 ±车头两种，取更远离的那个。于是「先倒着拉开、同时把车头转到
切向、转好了再切前进」自然涌现。用例覆盖 36×5 个相对方位，全部满足该不变量。

## ❌ 驳回：开局躲 10s 再进场

队友的观察「绝大多数玩家开局都会打」**是对的**，但推论「所以我们该躲」被数据否掉。

真机 46 局，前 10s：

```
我方  赢 2.33/局   输 0.72/局   →  对局净赚 +1.61/局   （胜率 76%）
      撞障碍 1.98/局           →  白丢 -1.98/局
      合计 -0.37/局
对手  平均净变 -2.25/局
```

**开局是我方胜率最高的阶段（3.2:1），而那 -0.37 全部来自撞石头，不是来自打架。**
躲 10s 会主动放弃 +1.61 的对局利润，去省一个应该用避障解决的 -1.98。

## 顺手记一个死代码 + 它为什么该继续死着

`max_attack_fraction_of_energy` **完全不起作用**：

```python
ceiling = max(bid, energy * frac)
value   = min(bid, ceiling)      # === bid，恒等
```

沙盒扫 0.55/0.45/0.35/0.25 四个值，四组结果一位不差（果实 12.22、垫底 12%）。

保留但写清它错在哪：出价低于对手 → 必输。把出价压到 threat 以下，等于把一次可能
的 +1 主动换成一次确定的 -1；「留给后续碰撞」也补不回来，因为后续那几次同样会
因出价不足而全输。真正该控的是**交战频率**和**选谁打**，不是压低单次出价。
