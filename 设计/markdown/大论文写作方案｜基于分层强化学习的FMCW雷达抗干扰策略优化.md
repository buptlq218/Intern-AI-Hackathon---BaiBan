### 2.2 帧级决策带来的连带修订（口径⑤，影响面最大）

确认 SINR 由 RDM 估计后，决策周期从 chirp 级（50 μs）变为帧级，以下数字与表述全文统一按此改写：

| 量 | 原（chirp 口径） | 改为（帧口径） |
|---|---------------------|---------------------|
| 一个时间步时长 | 60 μs | 7.68 ms（128 chirp × 60 μs PRI） |
| 一个 episode（30 步） | 1.8 ms | 230.4 ms |
| 元策略决策周期 K=3 / K=8 | 3 / 8 chirp | 23.0 ms / 61.4 ms |
| 特征窗口 W=12 / W=50 | 12 / 50 chirp | 92.2 ms / 384 ms |
| 策略持久化 min\_steps=5 | 5 chirp | 38.4 ms |
| EMA 响应时间（3~4 步） | 150~200 μs | 23~31 ms |
| 战术层实时约束 | \< 50 μs | \< 7.68 ms |

随之改写的论述有三处：
1. 物理一致性问题消解，原 §2⑥ 的隐患不再存在。帧级决策意味着一帧内 f\_c 与 t\_d 保持不变，慢时间维相位连续性完整保留，RDM 与多普勒测速正常可用，逐帧切换参数只影响帧与帧之间，不破坏帧内相干积累。这一点要在 2.1.1 末尾显式声明一段：它是"参数调整类抗干扰不损害目标检测性能"的前提，也是评审最容易追问的点。原计划写进第五章展望的"决策粒度与相干积累折中"一条删去，换为新的展望条目（见 5.2）。
2. 时间尺度分离的论证要重写（2.3.1 / 4.1.1）。原文的"微秒级战术 vs 数十至数百 chirp 的战略"改为：战术尺度 = 单帧 7.68 ms，瞬时 SINR 由当前 (f\_c, t\_d) 直接决定；战略尺度 = K 帧 23~61 ms，干扰源的时频分布模式需在数十帧（数百毫秒）跨度上才呈现稳定统计特征。两个尺度相差约一个数量级，分离的必要性论证不受影响，而且更好写：7.68 ms 与 384 ms（W=50）之间是 50 倍差距，比原来的 chirp/百 chirp 更有说服力。同时可以补一句物理直觉：230 ms 的 episode 内，相对速度 32 m/s 的干扰车会移动约 7.4 m，干扰的时延分布确有显著变化，动态场景假设成立。
3. 实时性叙述由"完全不可行"改为"需工程优化"（2.3.3 / 4.4.3 / 5.2）。按口径④仍给实测 99.6 ms，但对比基准变为 23 ms 的决策周期而非 50 μs 的 chirp 周期：RF 推理本身 0.3~0.5 ms 相对 23 ms 有约 46 倍余量，算法侧完全满足；当前 Python 实现的端到端 99.6 ms 超出决策周期约 4.3 倍，瓶颈在 12 维特征提取的实现方式（逐帧重算全窗口统计量而非增量更新），可通过增量式滑窗、定点化与 C/FPGA 实现优化，属工程问题而非算法瓶颈。战术层 DQN 单次前向需 \< 7.68 ms，此项提纲与专利均未给实测值，正文留 `【待填】`，建议你补测一次（一次 forward 的耗时，很快）。

**5.2 未来工作展望**〔1.5 页〕
五条，每条都由本文真实局限出发而非泛泛而谈（已按 §2.2 第 1 条替换原"决策粒度"一条）：
1. **oracle 依赖**：维度敏感性特征目前依赖 3×3 穷举扫描得到的 oracle SINR，实车部署需以干扰参数估计或在线 warmup 扫描替代，其估计误差对元策略判别精度的影响有待评估；
2. **工程实时性**：RF 推理本身相对 23 ms 决策周期余量充足，但当前 Python 实现的特征提取端到端开销约 99.6 ms，需改为增量式滑窗更新并经定点化、C/FPGA 实现后验证实时性；
3. **帧级决策的响应延迟**：以帧（7.68 ms）为决策单位保证了帧内相干积累的完整性，但也意味着对突发干扰的最快响应延迟为一帧；如何在"帧内参数不变以保多普勒处理"与"更快响应"之间取得折中（如帧长自适应、子帧级粗判），是值得研究的方向；
4. **干扰类型扩展**：本文仅处理相干干扰，非相干干扰需引入调频斜率等更多可调维度，元策略的标签空间也需相应扩展；
5. **多智能体**：现为单智能体非合作场景，未考虑其他车辆雷达同时执行抗干扰策略，可扩展为集中式训练分布式执行（CTDE）的多智能体分层框架。
